# راهنمای جامع API مدیریت فناوری بورس تهران (TSETMC Cookbook - E1-1)

> **وضعیت سند:** پیش‌نویس فنی (Technical Draft)  
> **تاریخ بررسی:** ۱۴۰۵/۰۸/۱۲ (2026-11-03) — پس از پایان ساعات بازار  
> **روش استخراج:** تحلیل ترافیک مرورگر (`DevTools / Network`) روی پایگاه tsetmc.com ← بازتولید درخواست‌ها با ابزار `curl` ← ذخیره نمونه‌های خام در دایرکتوری `docs/samples/`  
> **اصل اعتبارسنجی:** تمامی یافته‌ها مستند به فایل‌های نمونه خام هستند؛ گزاره‌های قطعی‌نشده صراحتاً با برچسب «فرضیه/تأییدنشده» تفکیک شده‌اند.  
> **آدرس پایه وب‌سرویس‌ها (Base URL):** `https://cdn.tsetmc.com/api` (تمام متدها: `GET`، بدون نیاز به نشست کاربری/لاگین، خروجی در قالب JSON)

## ۱. جستجوی ابزار مالی (Instrument Search)

* **هدف عملیاتی:** دریافت شناسه یکتا (`insCode`) و واکشی ابزارها (سهام عادی و قراردادهای اختیار معامله) بر اساس بخشی از نماد یا نام.
* **آدرس اندپوینت:** `GET /Instrument/GetInstrumentSearch/{text}`  
  *(رشته ورودی `text` باید به‌صورت URL-Encoded ارسال شود).*
* **دستور نمونه (cURL):**
  ```bash
  curl -s "https://cdn.tsetmc.com/api/Instrument/GetInstrumentSearch/%D8%B6%D8%AE" -o docs/samples/search_zakh.json
  ```
* **مستند نمونه خام:** `docs/samples/search_zakh.json` (جستجوی عبارت «ضخ»)
* **ساختار بدنه پاسخ:** شیء حاوی آرایه داده `{"instrumentSearch": [ ... ]}`

| فیلد | نوع داده | شرح فیلد | نمونه واقعی |
| :--- | :--- | :--- | :--- |
| `insCode` | String/Int64 | شناسه عددی یکتای ابزار در سامانه معاملاتی | `31459957843277944` |
| `lVal18AFC` | String | نماد فارسی درج‌شده روی تابلوی معاملات | `ضخود1161` |
| `lVal30` | String | نام کامل و ساختاریافته: `اختيارخ <پایه>-<strike>-<سررسید>` | `اختيارخ خودرو-450-1405/11/07` |
| `flow` / `flowTitle` | Int / String | بازار معامله؛ کد `3` معادل «بازار مشتقه» | `3` |
| `cgrValCot` | String | کد صنعت؛ در اختیارهای مشاهده‌شده مقدار ثابت `31` | `31` |
| `lastDate` | Int | پرچم وضعیت حیات نماد (فرضیه: `1` معادل فعال، `0` منقضی) | `1` / `0` |
| `insCode2..4` | String | مقادیر هم‌ارز با `insCode` (کاربرد در هسته معاملات مبهم) | — |

* **رفتار و مشاهدات ترافیک:**
  * قراردادهای **منقضی‌شده** نیز در خروجی جستجو بازگردانده می‌شوند (مانند `ضخود3069` با تاریخ سررسید ۱۴۰۲/۰۳/۰۳ و مقدار `lastDate: 0`).
  * فیلدهای `instrumentID` و `cIsin` در این اندپوینت مقدار `null` دارند؛ بنابراین کد ISIN باید از اندپوینت `GetInstrumentInfo` استخراج شود.
* **مسائل باز (Open Questions):**
  * آیا این اندپوینت سقف مشخصی برای تعداد رکوردهای بازگشتی (Pagination) دارد؟ (در جستجوی عبارت «ضخ» حدود ۴۰ رکورد ثبت شد؛ شیوه واکشی لیست کامل نمادهای منقضی نیازمند آزمایش است).

## ۲. اطلاعات شناسنامه‌ای ابزار (Instrument Info)

* **هدف عملیاتی:** استخراج کدهای استاندارد بین‌المللی (ISIN)، متادیتا و مشخصات ثبت‌شده برای تشکیل رجیستری ابزارها.
* **آدرس اندپوینت:** `GET /Instrument/GetInstrumentInfo/{insCode}`
* **دستور نمونه (cURL):**
  ```bash
  curl -s "https://cdn.tsetmc.com/api/Instrument/GetInstrumentInfo/31459957843277944" -o docs/samples/instrument_info_31459957843277944.json
  ```
* **مستند نمونه خام:** `docs/samples/instrument_info_31459957843277944.json`

| فیلد | نوع داده | شرح فیلد | نمونه واقعی |
| :--- | :--- | :--- | :--- |
| `insCode` | String/Int64 | شناسه یکتای ابزار | `31459957843277944` |
| `lVal18AFC` | String | نماد فارسی ابزار | `ضخود1161` |
| `lVal30` | String | عنوان کامل قرارداد | `اختيارخ خودرو-450-1405/11/07` |
| `lVal18` | String | نماد انگلیسی (حاوی تاریخ انقضا) | `IKCO-O-14051107` |
| `instrumentID` | String | شناسه ملی ابزار (ISIN یکتا) | `IRO9IKCO6P01` |
| `cIsin` | String | کد شناسایی ناشر/گروه (متفاوت با `instrumentID`) | `IRO9IKCO6P02` |
| `contractSize` | Number | اندازه قرارداد پایه در زمان انتشار | `1000` |
| `flow` / `flowTitle` | Int / String | بازار مقصد | `3` / `بازار مشتقه` |
| `sector.lSecVal` | String | صنعت دارایی پایه | `خودرو و ساخت قطعات` |
| `staticThreshold` | Object | آستانه نوسان مجاز قیمت (`psGelStaMax` و `Min`) | `100000` / `1` |
| `minWeek` / `maxWeek` | Number | دامنه نوسان هفتگی قیمت | `218` / `245` |

## ۳. مشخصات تفصیلی قرارداد اختیار معامله (Option Contract Details)

* **هدف عملیاتی:** دریافت مستقیم پارامترهای ریاضی قرارداد شامل قیمت اعمال ($K$)، تاریخ سررسید، اندازه قرارداد و شناسه **دارایی پایه**.
* **آدرس اندپوینت:** `GET /Instrument/GetInstrumentOptionByInstrumentID/{instrumentID}`  
  *(توجه: پارامتر مسیر این متد کد ISIN یا همان `instrumentID` است، نه `insCode`).*
* **دستور نمونه (cURL):**
  ```bash
  curl -s "https://cdn.tsetmc.com/api/Instrument/GetInstrumentOptionByInstrumentID/IRO9IKCO6P01" -o docs/samples/instrument_option_IRO9IKCO6P01.json
  ```
* **مستند نمونه خام:** `docs/samples/instrument_option_IRO9IKCO6P01.json`

| فیلد | نوع داده | شرح فیلد | نمونه واقعی |
| :--- | :--- | :--- | :--- |
| `insCode` | String | شناسه یکتای قرارداد | `31459957843277944` |
| `instrumentID` | String | کد بین‌المللی نماد (ISIN) | `IRO9IKCO6P01` |
| `strikePrice` | Float | قیمت اعمال مصوب | `450.00` |
| `contractSize` | Number | اندازه قرارداد در روز معامله | `1000` |
| `uaInsCode` | String | شناسه یکتای دارایی پایه (`insCode` سهم مادر) | `65883838195688438` |
| `beginDate` / `endDate` | String | تاریخ انتشار و سررسید به میلادی (`YYYYMMDD`) | `20261031` / `20270127` |
| `buyOP` / `sellOP` | Number | موقعیت‌های باز خرید و فروش (مطابق با تابلوی رسمی) | `12375` |
| `aFactor`, `bFactor`, `cFactor` | Float | ضرایب قانونی جهت محاسبه وجه تضمین | `0.2` / `0.1` / `10000` |

* **مسائل باز (Open Questions):**
  * آیا این اندپوینت برای قراردادهای منقضی‌شده پاسخ معتبر بازمی‌گرداند؟
  * صحت ساختار خروجی برای قراردادهای اختیار فروش (`ط...`) باید با نمونه‌های مجزا اعتبارسنجی شود.

## ۵. تاریخچه قیمت‌های روزانه (Daily Historical Prices)

* **هدف عملیاتی:** استخراج سری زمانی قیمت‌های پایانی برای تحلیل تاریخی و بک‌تست الگوها.
* **آدرس اندپوینت:** `GET /ClosingPrice/GetClosingPriceDailyList/{insCode}/{n}`  
  *(پارامتر `n`: تعداد سوابق؛ ارسال مقدار `0` کل داده‌های تاریخی موجود قرارداد را برمی‌گرداند).*
* **دستور نمونه (cURL):**
  ```bash
  curl -s "https://cdn.tsetmc.com/api/ClosingPrice/GetClosingPriceDailyList/56490941862491615/0" -o docs/samples/daily_list_56490941862491615_0.json
  ```
* **مستند نمونه خام:** `docs/samples/daily_list_56490941862491615_0.json` (مربوط به نماد `ضخود9060`)
* **ساختار پاسخ:** شیء حاوی آرایه `{"closingPriceDaily": [ ... ]}`، **مرتب‌سازی‌شده از جدیدترین به قدیمی‌ترین رکورد**.
* **رفتار و مشاهدات ترافیک:**
  * روزهای پایان هفته تقویمی (پنج‌شنبه و جمعه) فاقد هرگونه رکورد داده هستند.
  * روزهایی که جلسه معاملاتی برگزار شده اما معامله‌ای انجام نشده است (`zTotTran: 0`) در آرایه وجود دارند (مانند تاریخ `20260826`). در نتیجه صرف وجود سطر به معنی ثبت حجم معامله نیست.
* **مسائل باز (Open Questions):**
  * عمق تاریخچه دارایی پایه (مانند خودرو) با پارامتر `0` تا چند سال گذشته قابل بازیابی است؟ رفتار مقادیر عددی غیر از صفر برای متغیر `n` دقیقاً چیست؟

## ۷. مکانیزم‌های محدودسازی و مدیریت Rate Limit

* **گزارش رویداد مسدودی (Block Event):** در تاریخ ۱۴۰۵/۰۸/۱۲ ساعت ۲۰:۰۸، پس از ارسال ۲۰ درخواست طی بازه ۴۰ دقیقه‌ای (با کاهش فواصل پایانی به ۳ ثانیه)، سرور به‌جای بدنه JSON پاسخ HTML با مضمون «دسترسی شما بدلیل مسائل امنیتی مسدود شده است» بازگرداند (`docs/samples/blocked/`). این مسدودی بعد از گذشت ۳۰ دقیقه به شکل خودکار برطرف شد (بلاک موقت مبتنی بر IP).
* **رهنمودهای فنی برای توسعه خزنده (Crawler Architecture):**
  1. **کنترل نرخ ارسال (Throttling):** فراخوانی‌ها باید با اعمال فواصل تصادفی (Exponential Backoff همراه با Jitter) کنترل شوند.
  2. **اعتبارسنجی بدنه پیش از تحلیل:** کد وضعیت HTTP ملاک تایید پاسخ معتبر نیست؛ سرور ممکن است در وضعیت `200 OK` متن صفحه مسدودی را ارسال کند. بررسی هدر `Content-Type: application/json` ضروری است.
  3. **مدیریت قطعی با Circuit Breaker:** در صورت مشاهده نشانه‌های بلاک یا تغییر Content-Type، عملیات اسکرپینگ باید بلافاصله متوقف و وضعیت اعلام گردد.

## ۸. پاسخ مستند به پرسش‌های ارزیابی فنی فاز ۱

1. **شناسه یکتای پایدار (Primary Key):** تنها شناسه یکتا و قطعی `insCode` است. نماد متنی فارسی (`lVal18AFC`) به دلیل امکان تخصیص مجدد پس از انقضا قابل اتکا نیست و ISIN نیز در خروجی جستجو با مقدار `null` برمی‌گردد.
2. **استخراج ارکان اصلی قرارداد:** با ارسال ISIN به اندپوینت بخش ۳، مقادیر `strikePrice`، `endDate` و `uaInsCode` (سهم پایه) به صورت مشخص دریافت می‌شوند. جهت تشخیص سریع نوع Call/Put، پیش‌وند «ض» و «اختيارخ» در برابر «ط» و «اختيارف» ملاک تفکیک است.
3. **تفکیک نمادهای فعال از منقضی:** متد جستجو هر دو دسته را بازمی‌گرداند؛ فیلد `lastDate` مبنای فیلتر اولیه است. مرجع لیست کامل و متمرکز کل اختیارهای فعال بازار، در اندپوینت دیده‌بان سراسری نهفته است که در کارهای آتی استخراج خواهد شد.
4. **ساختار داده‌های روزانه و تیک:** سوابق روزانه در اندپوینت بخش ۵ مستند شد. ساختار ریزمعاملات درون‌روز (تیک) هنوز استخراج نشده است.
5. **انطباق داده‌های تیک با رکورد روزانه:** داده‌های ریزمعاملات باید از نظر مجموع حجم (`qTotTran5J`)، ارزش (`qTotCap`)، تعداد (`zTotTran`) و قیمت‌های حدی (`priceMin`/`priceMax`) تطبیق کامل با ردیف همان روز در جدول روزانه داشته باشند.
6. **شناسایی روزهای غیرمعاملاتی:** روزهای تعطیل رسمی و پایان هفته اصلاً سطری در جدول تاریخچه ندارند؛ اما روزهای معاملاتی بدون معامله با مقدار `zTotTran = 0` ثبت می‌شوند.
